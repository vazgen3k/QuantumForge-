### Вывод по эмбеддингам

Для QuantumForge Software лучше использовать локальные Sentence-Transformers. Главная причина — база знаний содержит внутреннюю и потенциально конфиденциальную информацию: архитектурные решения, регламенты, PDF-спецификации заказных проектов, документы поддержки и политики. Отправлять весь корпус документов во внешний embedding API рискованно.
Для MVP можно выбрать multilingual Sentence-Transformers модель, потому что у компании международный контекст: Финляндия, Эстония, скандинавские клиенты, вероятно, документы есть на английском, а часть внутренних запросов может быть на русском. Для повышения качества позже можно добавить reranker.

#### Вывод по векторной базе

Для текущего проекта предпочтительней FAISS.

Причины:

1. Он быстрый и подходит для semantic search по dense embeddings.
2. Его легко встроить в Python-приложение без отдельного сервера. 
3. Он бесплатный и не требует дополнительной инфраструктуры. 
4. Для MVP RAG-бота объёма QuantumForge достаточно, особенно если грамотно chunk-ить документы и хранить индекс на диске.


### Рекомендуемая конфигурация сервера

Для RAG-бота нагрузка делится на две части:

1. индексация документов — парсинг, chunking, создание эмбеддингов, запись в FAISS;
2. ответ на запрос пользователя — embedding вопроса, поиск в FAISS, формирование prompt, вызов LLM.

### Конфигурация сервера 

Вариант 1. Полностью облачный

LLM: OpenAI или YandexGPT
Embeddings: OpenAI Embeddings
Vector DB: ChromaDB Cloud или managed storage
Плюсы: самый быстрый запуск, минимум инфраструктуры, хорошее качество.
Минусы: документы и запросы уходят во внешнее облако, что рискованно для конфиденциальных данных и аудитов.

Оценка: подходит для прототипа на публичных или обезличенных данных, но не лучший вариант для всей базы QuantumForge.

⸻

Вариант 2. Полностью локальный

LLM: open-source модель из Hugging Face
Embeddings: Sentence-Transformers
Vector DB: FAISS или ChromaDB self-hosted
Плюсы: максимальная безопасность, контроль данных, отсутствие платы за токены внешнему провайдеру.
Минусы: нужен GPU-сервер, сложное развёртывание, поддержка, мониторинг, MLOps, вероятно, ниже качество ответов без тонкой настройки.

Оценка: лучший вариант для очень чувствительных данных, но дорогой и сложный для старта.

⸻


Вариант 4. Гибридный

LLM: облачная для обычных документов + локальная LLM для конфиденциальных документов
Embeddings: локальные Sentence-Transformers
Vector DB: FAISS на старте, ChromaDB self-hosted при росте требований
Плюсы: баланс качества, безопасности и стоимости; можно маршрутизировать запросы по уровню конфиденциальности.
Минусы: архитектура сложнее, нужно классифицировать документы по sensitivity level.

Оценка: лучший долгосрочный вариант для QuantumForge Software.
